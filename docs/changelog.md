# Changelog

The release history is generated from the conventional-commit subjects
between release tags, one section per tag, newest first. It is published in
three places, all from the same renderer (`.ci/_changelog.py`), so they cannot
drift:

- [CHANGELOG.md](../CHANGELOG.md) in the package itself — the whole history
- the [GitHub releases page](https://github.com/tumblehead/TumblePipe/releases),
  alongside the signed per-platform archives (Windows, Linux, macOS arm64)
- the version page on [TumbleTrove](https://tumbletrove.com)

See [Changelog](development.md#changelog) in the development guide for how the
file is regenerated, and
[What a release's notes cover](development.md#what-a-releases-notes-cover) for
why the published notes can span more than one tag.

The full history follows on the online build of this documentation; the
offline copy links to the file above.
